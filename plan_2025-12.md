# PathScore Modernization Plan (December 2025)

## Overview

PathScore is a Flask-based pathway burden analysis web application (~2016) that analyzes patient-gene mutation pairs against a pathways database. This plan modernizes the application to Python 3.12 with Docker Compose containerization.

**Target Configuration:**
- Python 3.12
- Docker Compose deployment (MySQL, Redis, Flask, Celery workers)
- Flask-Security-Too for authentication
- **Optional Celery** - can run with `PARALLEL_MODE=threads` or `off`
- **Local/Single-User Mode** (future phase) - bypass auth for personal use
- MDS visualization kept but deprioritized

│   ├── demo/                 # Public demo blueprint

**Existing PARALLEL_MODE Support** (in [app/config.py](app/config.py) and [app/decorators.py](app/decorators.py)):
- `off` - Synchronous execution, no task queue
- `threads` - Background threads (no Celery required)
- `celery` - Full Celery task queue with Redis

This means Celery is **already optional** - we just need to ensure this continues working after modernization.

## Phase 1: Infrastructure Foundation

### 1.1 Create Complete Docker Compose

**New file: `docker-compose.yml`**

Services to define:
- `mysql`: MySQL 8.2 with health checks, data persistence
- `redis`: Redis 7 Alpine (optional, only needed if PARALLEL_MODE=celery)
- `flask`: Application container with gunicorn
- `celery-worker`: Celery worker (optional profile, only starts when needed)

```yaml
# Key addition: Use Docker Compose profiles for optional services
services:
  redis:
    profiles: ["celery"]  # Only starts with --profile celery
    # ...

  celery-worker:
    profiles: ["celery"]  # Only starts with --profile celery
    # ...
```

**Usage:**
```bash
# Without Celery (threads mode)
docker compose up -d mysql flask

# With Celery
docker compose --profile celery up -d
```

Based on `python:3.12-slim-bookworm`:

## Phase 7: Local/Single-User Mode (Future)

**Goal:** Allow running PathScore locally without user accounts. All projects belong to a single implicit user.

### Design:

Add `LOCAL_MODE` environment variable:
```bash
LOCAL_MODE=true  # Enables single-user mode
```

### Implementation approach:

**[app/__init__.py](app/__init__.py)**
- Check `LOCAL_MODE` at startup
- If enabled, create/fetch a default "local" user
- Store user ID in app config for reference

**[app/decorators.py](app/decorators.py)** - New decorator:
```python
def local_mode_login(fn):
    """Auto-login local user if LOCAL_MODE is enabled."""
    @wraps(fn)
    def wrapped(*args, **kwargs):
        if current_app.config.get('LOCAL_MODE') and not current_user.is_authenticated:
            local_user = User.query.filter_by(email='local@localhost').first()
            login_user(local_user)
        return fn(*args, **kwargs)
    return wrapped
```

**[app/pway/routes.py](app/pway/routes.py)**
- Modify `@login_required` routes to use `@local_mode_login` wrapper
- Or: Replace `login_required` with conditional decorator

**Routes affected:**
- `/` (index) - Show all projects for local user
- `/upload` - Associate uploads with local user
- `/scatter`, `/mds` - Access projects without auth
- `/results/<proj>` - Access any local project

### Conditional auth decorator:
```python
def auth_required(fn):
    """Login required unless LOCAL_MODE is enabled."""
    if current_app.config.get('LOCAL_MODE'):
        return local_mode_login(fn)
    return login_required(fn)
```

**Priority:** This can be deferred to a later phase after core modernization is complete.

**Approach:** Incremental - work through each phase sequentially, testing after each.

**Test Data Available:**
- Sample mutation file: [skcm_ns_500_sm.txt](skcm_ns_500_sm.txt)

**After each phase:**
1. Start Docker services (appropriate for the mode being tested)
2. Run pytest suite
3. Manual verification:
